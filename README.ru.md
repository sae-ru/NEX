# NEX — Neural Execution Language

**Язык нейронного исполнения.**

[English](README.md) · [Описание языка](docs/overview.ru.md) · [Начать работу](docs/getting-started.ru.md) · [Материалы для LLM](llm/LEARNING.md)

Главная идея NEX — передавать максимум точного смысла минимальным необходимым
числом токенов, сохраняя высокую производительность и безопасность исполнения.
Это цели проекта с проверяемыми критериями готовности.

NEX — язык и инструменты разработки для людей и языковых моделей. Вы пишете
читаемые исходники `.nex`. Компилятор проверяет типы, эффекты и границы исполнения,
хранит версионный семантический граф и генерирует нативный код через MLIR/LLVM
либо TypeScript для браузера. Готовая программа работает самостоятельно: LLM
при её исполнении не требуется.

```nex
module hello;
fn answer(x: i64) -> i64 { return x * 2; }
fn main() -> unit !{io} { print(answer(21)); }
test fn answer_is_42() -> unit { assert(answer(21) == 42); }
```

## За счёт чего ускоряется работа

- **Меньше повторного контекста.** Модель получает нужную возможность компилятора
  или ограниченный контекст символа вместо всего проекта.
- **Ошибки обнаруживаются раньше.** Проверки типов, эффектов и realms дают
  диагностику до исполнения. Тесты сравнивают поведение разных способов исполнения.
- **Меньше повторной компиляции.** Идентичность содержимого и кэш позволяют
  повторно использовать неизменённые нативные функции и объекты среды исполнения.
- **Нативное исполнение.** Приложение выполняет машинный код. Параллельные CPU-
  операции и провайдеры устройств имеют явно описанные границы проверки.

[Измерения и ограничения](docs/overview.ru.md#измерения) приведены отдельно.
В одном историческом целочисленном сценарии NEX был близок к C++
эталону с проверками арифметики. Это не доказывает паритет для любых программ. Полная экономия токенов
на принятых задачах разных LLM пока не измерена.

## Что можно разрабатывать

Реализованы модули, обобщения и трейты, неизменяемые агрегаты, Unicode-строки и
байты, проверяемая арифметика, типизированные ошибки и `finally`, структурированные
задачи, история графа, компоненты проектов, нативные библиотеки, HTTP/API и
браузерные адаптеры, отладка, профилирование и ограниченная скалярная верификация.

Один проект может разделять переносимую логику между нативным сервером и
TypeScript / React / Vite клиентом. Устройства подключаются явными доверенными
провайдерами. [Подробное описание](docs/overview.ru.md) разделяет возможности
языка и фактически проверенные платформы.

## Состояние разработки

Текущие исходники: **toolchain 0.155.0 / язык 0.27**, экспериментальная версия.
SDL-пример прошёл отдельную [приёмку Metal/Retina](docs/evidence/sdl-metal-retina-0.155.0.json)
на macOS ARM64, включая перенос пакета без исходников и SDK; это отдельная область
от полной приёмки языка и SDK.
Разрабатываются runtime-контракты для функций с эффектами и составными значениями;
полная приёмка этой версии ещё не завершена. Интеграция0.154 проверяется отдельно.
Объединение Windows и runtime-контрактов проходит проверку. Результаты родительских
Mac0.153 и Windows0.152.1 относятся к прежним исходникам; общей версии нужны новые испытания.
Принятая сборка 0.152.1 на macOS ARM64 прошла все 285 групп CTest. Development SDK
прошёл по 40 этапов в перемещённой и восстановленной установках. Дополнительно прошли 126 тестов
production UI/Workers в Chromium, Firefox и WebKit. Области проверки описаны в
[отчёте об отладчике](docs/evidence/lldb-resume-0.152.1.json) и
[руководстве по runtime-контрактам](docs/runtime-contracts.md).
Фактические возможности сообщает выбранный `nex describe`. Принятые SDK,
коммиты и области аппаратной проверки указаны в [состоянии поставки](docs/releases/0.152.1.json).

Для Apple M5 Max есть [испытания OpenCL U8 Add/Affine на физическом GPU](docs/evidence/macos-opencl-0.151.1.json).
Результаты ускорителей Linux CIX/RK сохраняют [версию 0.151.0](docs/evidence/accelerators-0.151.0.json).
[Локальный компилятор Windows](docs/windows-host.md) собирает и запускает x64
`.exe` непосредственно в Windows, включая CPU/tasks/files и SQLite.
Предыдущая [приёмка target-кода](docs/windows-native-acceptance.md) сохраняет
раздельные результаты WSL producer, Windows execution и CUDA driver prerequisite.
У [SDL-примера «Крестики-нолики»](examples/tic-tac-toe/README.md) общие исходники
NEX/SDL и нативные скрипты сборки для Windows, macOS и Linux. GPU и перенос
автономного пакета проверены на прежнем Windows-снимке. Текущий пересчёт Retina
прошёл отдельную Mac/Metal-приёмку; повторный Windows-запуск и Linux остаются открыты.
Нативный Windows-компилятор прошёл **274/274 групп CTest**.
CUDA U8 Add/Affine из NEX прошла 35 аппаратных сценариев на RTX 3090;
[текущий Windows-отчёт](docs/evidence/windows-native-2026-11-01.json)
отделяет этот результат от полной регрессии и приёмки SDK.
Полная приёмка Windows-hosted SDK, Metal compute, Apple NPU, общая GPU-компиляция,
полная мобильная/UI-поставка и остальные пункты [PLAN](PLAN.md) ещё открыты.

## Сборка и использование

Начните с [актуальной инструкции](docs/getting-started.ru.md). Для сборки из
исходников нужны C++20, CMake 3.25+, LLVM/MLIR 22.1.x, SQLite, OpenSSL 3, Z3 и
Python 3.10+. Для веба/TypeScript нужны также Node.js 22.18+ и npm с lock-файлом проекта.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 4
ctest --test-dir build --output-on-failure
cmake --install build --prefix /absolute/path/to/nex-sdk
```

Каталоги `bin/nex` и `share/nex` должны оставаться вместе. Обычная установка
CMake использует зависимости компьютера сборки; [переносимый SDK](docs/sdk.md)
упаковывается и проверяется отдельно.

```sh
nex doctor --json
nex describe --kind index --json
nex init /path/to/my-app
```
