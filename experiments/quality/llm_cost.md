# Offline LLM task-cost ledger

`llm_cost.py` summarizes recorded trials for NEX, C++ and Python. It makes no
network requests and does not run a model, an acceptance command or a price
lookup. Actual multi-model experiments and the quality targets in
[quality.md](../../docs/quality.md) remain open.

From a source checkout:

```sh
python3 experiments/quality/llm_cost.py /path/to/campaign/ledger.json \
  --output /path/to/new-summary.json
```

From a matching installed SDK:

```sh
python3 /path/to/sdk/share/nex/tools/llm_cost.py /path/to/campaign/ledger.json
```

Requires Python 3.10+. The output path must be new. Exit0 means that the declared
matrix and token usage are complete; exit1 means missing trials or unknown usage;
exit2 means invalid input, an evidence-pin mismatch or an I/O error. Synthetic
control data can exit0; that is an accounting check, not an actual experiment.

## Record a campaign

Agree on the tasks and acceptance criteria before generating candidates. Pin
the common protocol file: permissions, tool access, budgets, stopping rules,
starting snapshots, task order, repetitions and treatment of warm/cold context.
Use the same task/acceptance contract for each language. Record actual model
snapshots, tokenizer IDs and settings; model aliases for the same provider and
revision do not count as independent models. Review comparable C++/Python
implementations and acceptance harnesses separately. These baselines are not
generated by the ledger tool.

The ledger is UTF-8 JSON, with this top-level shape:

```json
{
  "schema": "nex.llm-cost-ledger/1",
  "data_kind": "observed",
  "languages": ["nex", "cpp", "python"],
  "repeats": 2,
  "protocol": {"path": "protocol.md", "sha256": "<64 lowercase hex characters>"},
  "models": [{
    "id": "model-snapshot-id",
    "provider": "provider-id",
    "revision": "actual immutable revision",
    "tokenizer": "actual tokenizer-id",
    "settings_sha256": "<64 lowercase hex characters>"
  }],
  "tasks": [{"id": "shared-type-edit", "contract_sha256": "<64 lowercase hex characters>"}],
  "runs": []
}
```

Angle-bracket values are placeholders, not valid pins. This empty `runs` array
produces an incomplete matrix. Each model/task/repeat/language slot needs its
own terminal trial. Repeats start at0. Do not discard unsuccessful trials or
replace them with a later successful run. All repair calls within a trial stay
in that trial. A missing slot is reported explicitly.

A trial has these fields:

```json
{
  "id": "unique-trial-id",
  "model": "model-snapshot-id",
  "task": "shared-type-edit",
  "repeat": 0,
  "language": "nex",
  "status": "accepted",
  "wall_ms": 12345,
  "acceptance": {"path": "trial/acceptance.json", "sha256": "<64 lowercase hex characters>"},
  "calls": [{
    "id": "provider-request-id",
    "evidence": {"path": "trial/provider-response.json", "sha256": "<64 lowercase hex characters>"},
    "usage": {"input_tokens": 1200, "cached_input_tokens": 200, "output_tokens": 300},
    "confirmed_cost": null
  }]
}
```

Statuses are `accepted`, `failed`, `timeout` and `budget_exhausted`. Record every
attempted model call, including failed requests. Request IDs must be unique per
provider across the campaign; assign a producer trace ID if a failed request has
no provider ID. Preserve the raw response or failure record and its SHA256.
All evidence paths use `/`, stay within the ledger directory and refer to
bounded regular files. Artifact contents are hashed locally and are not copied
into the summary.

Normalize usage from the actual provider record. `input_tokens` includes cached
input; `cached_input_tokens` is a subset, not an extra charge in the token total.
`output_tokens` includes any reasoning tokens already included by the provider.
Do not add a reasoning subtotal twice. Count every call's complete input,
including repeated prompts, documents, tool responses and repaired context.
`usage: null` means unavailable usage and prevents a complete token comparison.
Do not estimate missing tokens from bytes, file length or a different tokenizer.

`confirmed_cost` is either null or, for example,
`{"amount":"0.001234","currency":"USD"}`. Use confirmed recorded amounts,
not a guessed rate card. Unknown cost is counted explicitly; currencies are
reported separately and are never added together. Token comparisons can still
be complete when billing data is unavailable. Amounts use plain nonnegative
decimal strings, up to12 digits before and after the decimal point.

The normalized acceptance receipt binds the trial to the agreed contract:

```json
{
  "schema": "nex.llm-acceptance/1",
  "trial_id": "unique-trial-id",
  "contract_sha256": "<64 lowercase hex characters>",
  "passed": true,
  "checks": [{"name": "agreed-acceptance-suite", "exit_code": 0}]
}
```

Produce this record from the reviewed acceptance harness, not the model's
claim that it succeeded. Preserve commands, test outputs, starting/final source
pins and compiler/runtime identities in the trial evidence. A passed receipt
requires nonempty checks with zero exit codes; other terminal statuses require
`passed:false`. The summarizer checks the receipt's binding and consistency.
It does not execute checks or prove that their semantics satisfy the task.

## Read a summary

For each model and language, the primary metric is:

`sum(input_tokens + output_tokens for all trials) / accepted_trials`

The numerator includes failed trials and all repair calls. A failure-free sample
is not substituted for this total. Zero accepted trials, unknown usage or a
missing matrix slot leave this metric null. Counts with incomplete usage are
labelled `known_*`. Cached and uncached input are separate subtotals.

The report also gives success counts, terminal statuses, call counts, total wall
time, median trial tokens and nearest-rank p95 trial tokens, including failures.
Ratios and medians use exact rational numerator/denominator objects. A comparison
uses the same model's NEX and baseline totals per accepted trial and also reports
whether the observed NEX success rate is at least the baseline's. Zero baseline
token cost produces a null ratio. There is no pooled claim across models.

`eligible_for_comparison_review` requires a complete observed-labelled matrix,
known usage, at least three different provider/revision pairs and two repeats.
This is a prerequisite for review. The tool cannot authenticate provider usage,
billing, model independence, omitted calls, acceptance semantics or protocol
fairness. These limitations are explicit false fields in every summary. Review
the pinned raw evidence and actual experiment before claiming savings.

The checked-in tests use synthetic records only. They verify arithmetic,
failure retention, evidence binding and rejected ledgers. They do not establish
NEX's30% token-reduction target or any C++/Python parity.
