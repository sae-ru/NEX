# Genuine023 mixed File/FFI migration histories

Four archives were produced by ordinary check/eval/ffi commands of the actual
installed SDK0.133.5, source language023. C11 and C++20 pinned producers each
have a stream and a whole-file history, with three checked semantic revisions
per history. SQL retains the exact sixteen tables, schema, rows and logical
identities. No fixture language or revision metadata was retagged. The source
archive includes producer C source, exact signature descriptions, original
manifest and hashes; it includes no binary or operator credential.

Each program combines an actual File or whole-file read with a genuine opaque
Session returned by typed C FFI. Session aliases cross a task capture and a
pure forwarding provider before their value is read and the owner is closed.
Retained023 stream execution fails with E_TASK_UNIMPLEMENTED before allocating
the foreign object. Retained023 whole-file execution succeeds. Both histories
execute successfully after explicit private024 migration. Factory/destructor
markers, module lifetime and external capacity verify real ownership cleanup.

The conformance test rechecks all twelve original identities, preserves every
old table row and physical source/manifest, appends one024 revision, repeats the
migration idempotently, and checks AST/native results. Native execution hides
source files. A pure client is emitted and executed separately, without server
file or foreign authority. False origin language, stale HEAD and implicit
synchronization are rejected without modifying the store. An optional pinned
--retained-sdk reruns original revisions after migration.

Producer binaries are rebuilt with fixed install names and no debug paths.
The capture verifies byte equality in two distinct directories. macOS keeps
the content-derived LC_UUID required by dyld. Original foreign pins are never
rewritten inside archived023 rows. If the current platform/compiler or sanitizer
changes a producer binary, a separately recorded candidate projects exactly
the three foreign manifest references to a new explicit host catalogue. The
original bundle is verified before this candidate is checked. Only the new024
revision records that projection; the sixteen-table preservation check remains.

Old runtime execution is claimed only if the original pinned producer can
actually be rebuilt. Otherwise the report explicitly records unavailable old
runtime execution while still rechecking original identity. This is not proof
of old execution on another platform. Independent current SDK/platform and
sanitizer acceptance remain required. C FFI still cannot construct or transport
File values. No public024 CLI, syntax, grant or implicit migration is added.
