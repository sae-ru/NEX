# Стоимость трёх правок NEX в Codex, 22 ноября 2026 года

На трёх одинаковых задачах обновлённые инструкции и инструменты SDK потребовали **353 520 токенов вместо 529 630**. Экономия составила **176 110 токенов (33,25%)** и **10,559 с (9,12%)** от начала работы модели до независимой приёмки. Модель довела до принятия все три решения в каждой серии. Запущено шесть отдельных сессий реального Codex, без подстановки оценочных токенов. [Полные результаты по задачам](evidence/codex-maintenance-0.281.0-2026-11-22.json).

| Задача | Токены до → после | Время с приёмкой до → после | Результат обеих версий |
|---|---:|---:|---|
| Исправить подсчёт Unicode-символов в сводке | 105 962 → 69 235 | 27,817 → 23,595 с | Принято |
| Реализовать ограниченную задержку повторной попытки для любого i64 | 144 005 → 88 433 | 36,677 → 28,604 с | Принято |
| Изменить межмодульный API очереди и сохранить прежний интерфейс | 279 663 → 195 852 | 51,224 → 52,960 с | Принято |
| **Всего** | **529 630 → 353 520** | **115,718 → 105,159 с** | **3/3 → 3/3** |

Сами сессии Codex заняли в сумме 107,896 с до и 97,403 с после. Разница с временем в таблице — внешняя приёмка. Предварительная установка SDK, разработка улучшений и сборка компилятора в это время не включены. Недостающие задачи, таймауты и повторные серии для выбора лучшего результата отсутствуют.

Вход и выход складываются один раз. Токены из кэша входят во входные, а токены рассуждений — в выходные. Некэшированного входа потребовалось на **12 536 токенов (16,35%) меньше**. Использовалась учётная запись ChatGPT. Клиент вернул статистику токенов, денежного списания за задачу не сообщил.

## Что поменяли и что действительно использовала модель

1. Сократили общую инструкцию с 4 058 до 1 833 байт. Для небольших правок она направляет модель к исходнику и тесту. К справке, индексу возможностей или графу она предлагает обращаться при конкретном вопросе. В исходной серии модель трижды запросила архивный контекст до первого сохранения графа и трижды получила E_REVISION.
2. Добавили чтение текущего файла через `nex context ENTRY --kind brief --symbol NAME --json`. Оно возвращает исходник функции, сигнатуры зависимостей и имена прямых тестов. В отдельной копии настоящего Workboard ответ о функции workboard::client_app::update занял 3 801 байт, обычный контекст — 19 235. Короткий ответ явно сообщил об усечении тела. Граф на диске не создавался. [Описание команды](queries.md).
3. Для `nex test --json` ошибка E_ASSERT теперь содержит имя теста, выражение, аргументы точечного перезапуска и для прямых сравнений i64/bool — значения операндов. На исходной заготовке задержки CLI показал выражение policy::retry_seconds(0) == 1, слева 0, справа 1. Прежний бинарник возвращал E_ASSERT и строку без этих полей. [Описание диагностики](diagnostics.md).

В трёх маленьких проектах после изменения модель обошлась прямым чтением файлов. Ни одна сессия второй серии не вызвала brief и не получила новую диагностику E_ASSERT. Это измерение совокупного пользовательского сценария. По журналам заметное изменение поведения — меньше обращений к инструментам. Отдельный вклад двух новых функций в экономию модельных токенов здесь не измерен. На задаче очереди модель искала синтаксис record/struct, запросила несуществующий тип справки records, исправляла ошибку парсера и в итоге потратила на 1,736 с больше. Сценарий с навигацией по большой программе и исправлением уже упавшего теста — подходящая следующая независимая выборка.

## Как воспроизвести

Использован Codex CLI 0.169.0-alpha.11.1, модель gpt-6.2-sol, уровень рассуждения low, язык проекта 0.30. Исходная версия — коммит 26e78f53. Поле source_commit в квитанциях обозначает базовый Git HEAD на момент запуска. Вторая сборка включает изменения рабочего дерева; фактические бинарники и инструкции каждой серии закреплены отдельными SHA-256.

Для каждой задачи обеим сериям дали одни и те же байты запроса и исходных файлов. Каждая сессия началась с чистого каталога. На вход модели попадали задание, рабочий проект, соответствующая инструкция и вывод средств разработки. Контроллер после выхода модели переносил только изменяемые исходники в отдельную чистую копию и запускал видимые и закрытые проверки в интерпретаторе и нативном режиме. Для миграции интерфейса подмена реализации отдельно проверяла, что клиент действительно обращается к новому API. Ошибочные заготовки и независимые рабочие решения проверены до начала серии. [Протокол, фикстуры и команды запуска](../experiments/quality/codex-maintenance/README.md).

Один прогон каждой задачи на один вариант, фиксированный порядок «до → после», маленькие проекты на одном Mac. Кэш сервиса и его текущая нагрузка влияют на наблюдаемые задержки. Эти результаты относятся к разработке на NEX. Для сравнения с Python/C++, оценки крупных систем или скорости созданных программ потребуются собственные измерения.
