# Local Qwen3.8 27B task comparison — 2026-11-11

**The current NEX workflow did not save tokens in this experiment.** With the
selected local Qwen3.8 27B Q8_0 revision, acceptance passed 4/20 NEX trials,
14/20 C++ trials and 20/20 Python trials. NEX consumed more total tokens and
had lower acceptance. This is an observed negative result for this model,
toolchain and workload; it does not establish results for other models or tasks.

| Language | Accepted trials | Model requests | Input tokens | Output tokens | All tokens, including failed trials |
| --- | ---: | ---: | ---: | ---: | ---: |
| NEX | 4/20 | 215 | 810,324 | 10,890 | 821,214 |
| C++ | 14/20 | 130 | 235,215 | 19,419 | 254,634 |
| Python | 20/20 | 134 | 197,784 | 14,772 | 212,556 |

Dividing each language's **entire token total by its number of accepted trials**
gives 205,303.5 / 18,188.14 / 10,627.8 tokens respectively. The NEX ratio is
about 11.29× C++ and 19.32× Python. This failure-amortized workload statistic
does not mean those languages solved the same accepted task set. Successful
trials alone must not be selected to conceal failed attempts.

## What was measured

The user chose one already installed local model; no paid API or other model
was used. The [registered ten-task protocol](../experiments/quality/llm-campaign-v1/protocol.md)
has three language counterparts and two repeats: 60 ordered trials. Source was
frozen at`67da05c`, toolchain0.165.0/language0.28. The compiler SHA256 is
`63cd6b70baedeea537e3ba84ce5c7186700c726be4436f495150856bcddbf992`.
The GGUF revision is`f0fc43cfd802bd87bc7b95f2120553a6407848e3229126b623cc397427857e8a`.
The actual selected runtime uses 16,384 context tokens, one parallel request,
reasoning off, temperature 0 / top_p 1 / top_k 40 / min_p 0 / repeat_penalty 1 and no DraftMTP.

Each trial allows 11 author requests and one fresh stateless local source-review
request; 900 seconds includes checks/review. The prompt has a 48,000-byte UTF-8
cap, distinct from token counts. Observed 60,000 tokens is a soft stopping
threshold. The author sees its starting files, neutral contract/visible cases,
bounded feature documentation and its own previous tool feedback; it has no
arbitrary shell, reference solutions or held-out cases. Tool checks use separate
compiler/runtime OS profiles and limits. Full hidden-case acceptance follows
submission once. A functionally correct submission also needs the counted
independent source-rule review by the same local model in a fresh context.

All 60 states are terminal: 38 accepted, 10 failed, 12 request-budget exhausted;
there were no trial timeouts. The 12 NEX budget outcomes reached the author
request limit. Four NEX submissions failed functional acceptance. C++ had four
functional failures and two source-review rejections. All 40 source-review
requests, including rejections, are in the 479 total requests and 1,288,404 tokens.
Original infrastructure pilots/readiness requests are separate.

## Evidence and limits

The [machine-readable record](evidence/llm-qwen38-27b-main-0.165.0-2026-11-11.json)
contains per-language totals, every task's statuses and source/ledger/audit/seal
hashes. The offline ledger reports a complete 60-trial matrix, with no missing
usage. The public `nex cost` command reproduced the same accounting summary. A separate audit checked each raw request/response hash and reconciled
all 479 input/output counts with native response statistics. It also bound
source-review rules, candidate hashes and review requests to each trial.
The worker exited normally and unloaded only its own model instance.

Cached/uncached split and confirmed monetary cost were not reported; they remain
unknown. Local inference does not establish zero electricity/hardware cost.
The ledger's multi-model review flag remains false by design: the user selected
one model, and no extra models are needed to complete this requested matrix.
Source review is model-assisted, not formal verification or a human judgement.
Two temperature-zero repeats are not independent stochastic samples.

Brief development metadata/build/control work overlapped collection and is
retained in the local host-activity records. Observed wall times are not an
exclusive-host latency benchmark. This experiment measures development token
cost/acceptance, not generated-program runtime performance or a portable SDK.
Raw transcripts, failures, source pins, original compiler bytes and the frozen
Git source archive remain locally sealed; they are not all embedded in the public
summary. Their original absolute paths/inode metadata were not rewritten.

## Next implementation work

The observed failures justify better bounded language entry and diagnostics,
not a claim of savings. For example, a failed NEX total still used unsupported
`+=` after receiving an E_PARSE diagnostic; the Unicode candidate returned the
whole input rather than the requested window. A failed C++ module update retained
a one-argument public wrapper while the contract required two arguments.

Next improve compact, compiler-validated syntax/feature examples, actionable
diagnostics and `nex explain`, plus the planned standard-library helpers. A later
matched study must have a new versioned protocol/input identity, retain this
negative result, count all retries and use the same user-selected local model.
Do not manually repair the measured candidates or replace failures with new runs.
