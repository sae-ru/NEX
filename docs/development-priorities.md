# Приоритеты улучшения NEX

Приняты предложения пользователя из14 пунктов. Ниже — проверка по исходникам
`182e45d` и реестру CTest от2026-11-10, а не повторение чисел из прежнего обзора.
В исходном аудите310 групп, меток нет. Текущий LLM-блок добавил две группы;
после campaign/local/collector/tier-блоков их318 на Mac. Все группы получили LABELS;
11-групповой core прошёл за12,36с. Полный исходный объём [PLAN](../PLAN.md) сохранён.

Сначала приводим LLM-входы к текущему языку, затем измеряем реальные затраты
моделей на принятые задачи. Подготовка повторяемой сборки/коротких проверок идёт
в том же направлении; полные платформенные прогоны остаются на согласованный
финальный этап. Старый SDK0.162 не становится целью вместо актуального0.165.

## Выполнено после аудита

LLM-вход приведён к текущему0.28: `features` сохранён и явно обозначен как legacy
partial summary, index рекомендует актуальные секции; общий валидатор проверяет
все зарегистрированные capability-поля с точными JSON-типами. Новый корпус
имеет9 реально выполненных проектов и6 отвергнутых программ; сохранены main/test
наблюдения reference/native Release/TypeScript и исходный0.27 snapshot. См.
[метки](../llm/corpus.json) и [воспроизводимый workflow](learning-corpus.md).
Это закрывает текущий блок пункта3, сохраняя последующую SDK/platform-приёмку.

`nex cost` реализован без второго движка учёта: выбранный compiler/SDK запускает
тот же офлайн-ledger, не открывает проект и не затирает существующий отчёт.
Подготовлены [протокол и10 контрактов](../experiments/quality/llm-campaign-v1/protocol.md)
с происхождением исходников и граничными случаями. Подготовка теперь создаёт
30 стартовых наборов; функциональная приёмка проверена30 эталонными решениями
и30 неправильными стартами на32 видимых/29 закрытых случаях. Проверка source-
правил отдельно привязана к хешам. Пользователь выбрал только локальную Qwen3.8 27B Q8_0,60 попыток
без платных API. Реализованы локальный API transport, полное SHA256-закрепление
весов и scoped macOS-изоляция компиляции/исполнения. Пробный запрос дал фактические
36 входных/6 выходных токенов; экземпляр выгружен. Неизвестный cache split остаётся
null, общий input/output учитывается. Сборщик, runtime/template/budget freeze и отдельный локальный source review
реализованы. Три инфраструктурных пилота сохраняют8 начатых слотов и69 запросов
с одним неизвестным usage; отказы не заменялись успешными. Исправлена передача
истории, JSON-обёрток и stdout-диагностики. Следующий пилот подтвердил передачу
реальной E_PARSE/строки/сообщения модели; её NEX-код всё равно не прошёл,
C++/Python приняты. Далее — основная матрица60 попыток; экономия пока не установлена.

Метки и11-групповой короткий цикл уже реализованы и проверены. Следующие результаты —
основное сравнение, пресеты/воспроизводимая сборка и CI. Учебный корпус не является сравнительным
экспериментом моделей и не доказывает экономию токенов.

## Ближайшая последовательность

1. Выполнено: согласовать discovery/corpus и закрепить текущий языковой вход.
2. `nex cost`, контракты и подготовка/приёмка стартовых проектов готовы как
   инструменты. Изолированный локальный runner и отдельный локальный review
   реализованы; собрать основную матрицу наблюдений;
   бухгалтерские synthetic tests не заменяют эксперимент.
3. Уровни тестов реализованы; далее CMake-пресеты, повторяемая подготовка SDK и CI.
4. Продолжить sanitizer/fuzz/agreement, diagnostics/stdlib/fmt/CLI/bench как
   завершённые функциональные блоки с короткими затронутыми проверками.
5. Закрыть оставшийся исходный функциональный план и выполнить одну согласованную
   финальную платформенную/SDK-приёмку, публикацию актуального main и очистку.

В этой последовательности остаются GPU/NPU/debug/profile/Apple NPU, остальные
языковые и браузерные расширения, mobile/native UI, Studio и конвертер проектов.
Этот документ не объявляет их реализованными и не отменяет прежних требований.
