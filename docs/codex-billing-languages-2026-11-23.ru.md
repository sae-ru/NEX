# Сколько стоит исправление одного счёта на NEX, C++ и Python

**Приняты все девять исправлений.** На этом дефекте Python быстрее всего дошёл до независимой приёмки (19,89 с). C++20 потребовал меньше всего токенов в целом (61 460), а Python — меньше всего при вычитании прочитанного из кэша входа (11 501). На NEX ремонт занял 25,69 с и потребовал 71 809 токенов, из которых 56 448 пришли из кэша.

## Время и токены на одно принятое исправление

| Язык | Принято | Сессия Codex, с | До приёмки, с | Полный расход | Вход из кэша | Вход вне кэша | Выход | Вход вне кэша + выход |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| NEX | 3/3 | 21,35 | 25,69 | 71 809 | 56 448 | 14 992 | 369 | 15 361 |
| C++20 | 3/3 | 17,71 | 20,89 | 61 460 | 45 653 | 15 526 | 281 | 15 807 |
| Python | 3/3 | 18,70 | 19,89 | 75 373 | 63 872 | 11 180 | 321 | 11 501 |

NEX использовал на 4,7% меньше полных токенов, чем Python, и на 16,8% больше, чем C++. После вычитания кэшированного ввода NEX оказался на 2,8% ниже C++ и на 33,6% выше Python. Из кэша пришло 79,0% входа NEX, 74,6% входа C++ и 85,1% входа Python.

Время одного принятого исправления NEX превысило C++ на 4,80 с и Python на 5,80 с. Из среднего полного времени на воспроизведение и независимую приёмку вне сессии Codex ушло 4,34 с у NEX, 3,18 с у C++ и 1,19 с у Python. Языки различались и по времени самой сессии Codex.

Во всех девяти сессиях Codex изменил только модуль учёта доступности склада и успешно запустил `./test` после правки. Внутри каждого языка все три правки побайтово совпали. Исправленный расчёт дал 21 день простоя, 9 оплачиваемых дней и остаток 2 079 центов. Все три реализации стартовали с одинаковой инструкции без вложенной подсказки об исходном модуле.

Три попытки на одном дефекте характеризуют именно этот ремонт. Например, NEX использовал от 71 379 до 72 275 полных токенов, а после вычитания попаданий в кэш разброс составил от 5 203 до 33 244. Порядок языков сбалансирован, но состояние серверного кэша между сессиями Codex контролировать нельзя.

Замер выполнен на одном Mac ARM64 с macOS 27.2.1. Использованы Codex CLI 0.169.0-alpha.11.1, модель `gpt-6.2-sol` с уровнем рассуждения `low`, NEX 0.30 / SDK 0.281.0, Apple Clang 21.0.0 (`-std=c++20 -O0`) и Python 3.14.9. Средние токены в таблице округлены до целого.

## Что исправлял Codex

Склад выставил счёт на 1 252 цента при ожидаемой сумме 2 079. Когда один период простоя целиком попадал внутрь другого, расчёт сдвигал назад конец уже учтённого интервала. При следующем пересечении он повторно вычитал часть дней из срока аренды. Этот дефект находился в одном из восьми модулей приложения. Та же реализация на NEX использовалась в [предыдущем эксперименте с контекстом и диагностикой](codex-multimodule-2026-11-22.ru.md).

Каждая из девяти свежих сессий Codex получила одинаковые текст задания, описание тарифов, входной счёт и команду `./test`. Модель сама выбирала, какие файлы открыть. Стартовые версии на трёх языках воспроизводили обе суммы. Порядок языков менялся между тремя последовательными блоками, так что каждый язык один раз оказался первым, вторым и третьим. Время на подготовку портов и запуск контрольных примеров вынесено за пределы замера.

Приёмка переносила изменённые производственные модули в чистый каталог. Эталон перебирал календарные дни и проверял дни простоя, оплачиваемые дни и все пять полей счёта на исходном примере и 13 дополнительных. Контроль с подстановкой суммы 2 079 прошёл открытый тест и провалил закрытый на всех трёх языках. Для NEX приёмка требовала успешного исполнения интерпретатором и в нативной сборке. Для C++ она компилировала и запускала открытый и закрытый тесты, для Python выполняла их интерпретатором.

Полное время отсчитывается от воспроизведения исходного сбоя до получения независимого вердикта, включая сессию Codex. Все затраты каждого языка делятся на число принятых исправлений. Полный расход токенов равен сумме всего входа и выхода. Кэшированный ввод входит в общий ввод. Сумма некэшированного входа и выхода показывает объём работы за вычетом чтений кэша. Цена в деньгах и длительность работы с принудительно холодным кэшем в эксперименте не измерялись.

## Почему замер повторили

В первом запуске прямой вызов Apple Clang из оболочки Codex не находил стандартный заголовок `cstdint`. В двух сессиях C++ модель сама вычислила путь к системному SDK. Это добавляло к ремонту работу по настройке компилятора. Предварительную серию остановили, путь к SDK включили в команду `./test` и заново запустили весь порядок из девяти сессий. В пяти завершённых предварительных сессиях зарегистрировано 344 865 токенов, включая 305 664 токена входа из кэша. Шестая была прервана без итогового счётчика. Этот дополнительный расход исключён из сравнения языков.
