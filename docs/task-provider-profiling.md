## Recording and source identity

The public project flow uses a configuration whose profile is
`"profile"`, then `nex project --kind profile --component app --configuration
measured --json`. Keep checked provider source and declared dependencies. Every
binary stage in the connected task cohort must carry the same instrumentation.
The executable entry in a connected task cohort must declare task. Pure provider
helpers and independent ordinary applications keep their own contracts. The final
task executable owns one root request, task executor, collector and checked
registry batch. Providers do not create collectors, active constructors, report
identity or executors. Static applications retain their embedded runtime;
shared providers import one common startup-linked runtime.

Each physical component emits an immutable registry and metadata accessor using
a separate32-byte registry ABI1. Existing task descriptors still point to their
original32-byte local source-site records. Batch registration preserves those
original address ranges and maps them to one dense run-local site index. It does
not copy tables and pretend descriptor pointers changed. Registration is bounded
to128 registries,16384 sites and16MiB text; duplicate components, overlapping
ranges, ambiguous source sites, unknown ABI or oversized metadata reject before
source execution.

A source invocation counts once over yields, calls, waits and worker changes.
An image crossing or resume is not another call. Task parent and spawned-task
origin relationships remain distinct. Pure helpers, concrete generics and local
callbacks use the same collector/TLS as task frames. The catalog includes every
actual physical definition, including selected unused exports and provider-only
generic specializations that the root Program never loaded. Such zero-call sites
remain present and checked; incompleteness flags cannot excuse their absence.

Checked source catalogs bind function canonical hash, function-source hash,
source-unit hash, source anchor/line, contract, component and physical image
owner. Root revision remains the selected application's revision. A provider-only
site has explicit captured-component identity and no invented root graph node ID.
Each independent executable registers only its own loaded closure. A common
runtime's union of code support does not widen a root's catalog, limits or grant.

## Measurements and limits

Metric meanings remain those of [native task profiling](profiling.md): source
thread CPU and active monotonic elapsed cover active source segments; logical
lifetime includes suspension/drain. Ready/wait/drain/executor measurements remain
separate scheduler facts. Overlapping lifetimes are not additive process time.
The managed Handle/Data pools retain shallow allocation meaning across image
creation/free; they are not total RAM or backing-storage measurements.

Inspect aggregate, timeline, memory and each clock completeness flag before
budgets. Event-only truncation, including events0, may preserve complete call and
shallow-memory aggregates. Other relevant drops or unavailable measurements
invalidate their budgets. Registration/callback metadata work does not become a
source invocation. No profiling hook, clock or collector callback belongs under
kernel or IO locks.

Raw3 additionally labels individual collector backing-capacity gauges:
`registry_record_capacity`, `registry_record_capacity_bytes`,
`registry_component_text_capacity_bytes`, `metadata_record_capacity_bytes`,
`metadata_text_capacity_bytes` and `site_lookup_capacity_bytes`. They describe
separate backing allocations/capacities. Text includes terminators and may overlap
inline string storage already counted by shallow records; adding these gauges
does not produce total RAM. Standalone task2 retains its existing fields.

Configured and lowered root execution limits still apply through providers and
pure helpers. Source server task/fs reads use the existing root grant. An unused
read export may require runtime read code while the selected root has no read
policy; a registry never grants authority. Cancellation and the first selected
fatal error suppress source admission and physically drain before completion
and report publication. Source errors must survive measurement drops or cleanup.

## External records

Instrumented providers use `nex.native-task-provider/3`, preserving the exact
static or shared base semantics and adding one strict profiling object. Its
`nex.native-task-profile/1` extension names registry ABI1,
`task-profile-catalog.json`, semantic catalog hash and ordered component
registries. Old provider1/2 and completion4/5 remain unchanged.

`nex.task-profile-catalog/1` records mode, artifact kind, physical owner and
ordered registries/sites. Artifact-local catalogs contain embedded definitions;
the application's expected batch catalog joins its actual loaded closure. These
hashes have different scopes. Semantic hashes exclude addresses, future image
SHA/UUID, report paths and root limits. Completed images separately pin actual
provider/catalog/image bytes. Schemas:
[provider3](../llm/native-profiled-task-provider.schema.json),
[catalog1](../llm/task-profile-catalog.schema.json).

The new instrumented path uses completion6, project linkage3, retained-build3,
application-request3 and profile build2. Raw/saved/session3 are separate from old
task2. Raw3 publishes a bounded registry-range map; its function rows must
exhaust the checked ordered catalog, including zero-call sites. Saved3 separately
retains verified source/component/image attribution and actual current-action
image pins. No executable embeds its own future output SHA in its identity.

## Capture, replay and copied output

Bind each profile/capture/replay/package action to its own checked command,
catalog and completed image closure. Captured workspace CWD/cache can legitimately
change runtime and final-image keys. Comparing a capture's keys or BLAKE3 index
to a separate normal-workspace package is invalid. Compare checked semantic
expectations between actions, then verify each action's own physical pins.

Retained outputs copy raw provider/catalog/build/debug/complete/report metadata
byte-identically, with bounded original-to-retained paths, hashes and sizes.
Replay rechecks captured source architecture and measures again with the matching
compiler. Packaging verifies original metadata and records a separate mapping to
relocated output SHA256. Assembly alone does not execute or measure source.
A copied instrumented application plus its fixed image closure may write raw3
without source/compiler resources; this does not authorize the compiler to
profile an arbitrary relocated package without verifying its provenance.

Only local macOS/Linux64 standalone application processes and reviewed native
project build/run/profile/package workflows are in the enabled slice. Profile
configuration test/build-test execution remains pending. Runtime load/unload, logical task
debugging across providers, combined debug/profile, Tracy task capture, HTTP or
foreign providers, authority/callable transport, binary-only checking,
reference/TypeScript profiling and other platforms remain pending. Actual source
regular-file tests and a controlled private physical-completion fence have
different evidence scopes. Sanitizer reports must state whether generated
provider IR, common runtime and driver were instrumented.
