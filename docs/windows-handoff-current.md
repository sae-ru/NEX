# Передача NEX: Windows 0.162.2 / язык 0.28 / task ABI 7

Актуальные исходники и поставки описаны в [записи 0.162.2](evidence/current-platforms-0.162.2-2026-11-08.json).
Полная приёмка нового Windows SDK ещё идёт. Версия в этом документе не означает
завершённый релиз. [Промпт нового чата](WINDOWS-CODEX-PROMPT.md) использует ту же
версию языка и сохраняет весь исходный PLAN.

## Что подтверждено

Текущий Windows SDK собран из одной установки исходников
`05f01d69da0fe1f782d1f4558ba350738eef5d94` — 2024 файла. Он включает поправки
Python для холодной worker-сборки, TCP sysroot, частных файлов AppContainer,
логических путей отладчика и длинных путей файловых тестов. Нативные C++-входы
сохраняют основу `78acb4395573f003807b48e1bb5694bf9630f347`; язык0.28 и ABI7
не менялись. Точные исходники каждой проверки закреплены в evidence.

Windows собрал все цели, обычную установку и прошёл девять целевых групп.
Новый переносимый SDK собран из
одной установки; перенесённая и восстановленная из архива копии прошли doctor.
Бинарный TCP-обмен прошёл в reference, Debug и Release; все соединения закрылись.
Это один TCP-сценарий, а не полный набор сетевой совместимости.

Тот же архив прошёл [десять настоящих AppContainer-случаев](evidence/windows-current-AppContainer-TCP-0.162.2-2026-11-08.json),
включая нативную компиляцию/исполнение, запреты доступа к исходникам/зависимостям
и TCP в reference/Debug/Release. SDK был read-only; частные каталоги и профили
удалены после завершения всех дочерних процессов. Ресурсы SDK не подменялись.

Тот же архив на RTX 3090 прошёл [35 native/reference CUDA-сценариев и 36 проверок](evidence/windows-SDK-CUDA-0.162.2-2026-11-08.json)
Compute Sanitizer: 35 native-приложений и context probe. Независимая сверка
576 сырых файлов подтвердила 66 физических завершений ядер без CPU fallback,
баланс всех журналов ресурсов и 36 нулевых error/leak summaries. Deadline
остаётся 2000 ms. Полная приёмка SDK и исходной Windows-матрицы ещё идёт.

- Windows compiler SHA256: `977058a8090bbfe6bf53b1e13bf53cf20a2f85a819bd01fd7ce523da466fb2d3`.
- Новый SDK archive SHA256: `1bda62f5148fe87a2d5303dd9e66eaca162db6994b920214439a53bc926a8f0f`.
- Архив: 264461348 байт, 8809 файлов. Публичный бинарный релиз ещё не загружен.

Первый SDK этого этапа прошёл 28 обязательных фаз и остановился на сборке
TCP-модуля: прямому вызову Clang не передавался выбранный SDK sysroot.
Новый архив содержит исправление. Более ранний архив `37ca8ebc…` отдельно прошёл
CUDA, но полный SDK-прогон остановился на логическом source breakpoint. Исправление
путей включено в текущий архив. Исходные неуспешные архивы и журналы сохранены;
их результаты не заменены успехом повторных прогонов.

## Продолжение проверки

Работайте с фактически выбранным текущим checkout и согласованным SDK.
Сначала проверьте Git HEAD/status, `nex doctor --json` и
`nex describe --kind index --json`. Сверяйте toolchain, language,
`compiler_build`, `descriptor_hash`, compiler/resources и реальные инструменты.
Прочитайте [Windows host](windows-host.md), [SDK](sdk.md),
[настройку OpenSSL](../tools/windows/openssl/README.md) и
[проверку CTest registry/JUnit](ctest-results.md).

Host CLANG64/UCRT и target LLVM-MinGW имеют разные C++ ABI. Для новой сборки
можно выбрать отдельный каталог через `configure-host.ps1 -BuildDirectory`.
Сохраните уже проверенный набор зависимостей; упаковка должна выбирать тот же
OpenSSL, что сообщает doctor, вместе с его конфигурацией, провайдерами и notices.
Не подменяйте DLL или ресурсы внутри уже проверяемого SDK.

Области этого Windows-этапа:

1. Полные 41 фаза установленного SDK с `--live --browser` для перенесённой копии
   на Python 3.10 и восстановленной копии на Python 3.14; всего 82 фазы.
2. CUDA 35 и Compute Sanitizer 36 прошли на закреплённом выше архиве. Сохраните
   receipts и идентичности провайдера, компилятора, драйвера, headers и бинарников.
   Изменения соответствующих входов требуют новой аппаратной проверки; правка
   описаний не является основанием повторять неизменённый прогон. Общий GPU
   codegen и дополнительные Windows API остаются отдельной реализацией.
3. Актуальная исходная матрица с точным registry и JUnit. В конфигурации текущего
   стенда зарегистрированы 302 группы. Положительный IPv6 намеренно ограничен;
   `task_dns_source`, `task_dns_delivery`, `task_tcp_source`, `task_tcp_delivery`
   не приняты. Проверка оставшихся 298 групп и профиль
   `windows-ipv6-denied` в SDK не доказывают прохождение всех 302 групп.
4. Проверка заявленной области изоляции, GUI/GPU/DPI и оставшихся Windows API.
   Обычный пользовательский токен и успешный doctor не доказывают изоляцию.

Если исходный проект или SDK уже проверяется другим процессом, дождитесь его
завершения. Проверяйте сам процесс/handle, а не только оставшийся файл состояния.
Тайм-аут опроса не означает завершение. Сохраняйте исходный сбой, source/IR,
stdout/stderr и точные команды; повторяйте после подтверждённого исправления.
Настройки намеренно ограниченного IPv6 и права исходного проекта сохраняются.

[Старый Windows 0.152.1 результат](evidence/windows-native-2026-11-01.json) и
[его SDK/CUDA](evidence/windows-sdk-2026-11-01.json) остаются историческими
квитанциями своих снимков. Они не закрывают новую проверку 0.162.2.

## Публикация и полный проект

Обновите компактные evidence и описания EN/RU после фактических результатов.
Пользователь разрешил commit/push актуального проверенного SDK в main;
сохраняйте чужие изменения и историю, без force-push. Новая бинарная поставка
требует собственного точного архива и завершённых проверок своей области.

Общая генерация GPU/NPU-кода, Metal compute, Apple NPU, Windows ARM64,
мобильный/native UI, NEX Studio, конвертер проектов и реальные измерения
полной стоимости разных LLM остаются в [PLAN](../PLAN.md). Аппаратная проверка
готового провайдера не завершает эти пункты.
