# Private modular logical debugging

Toolchain 0.135.29 extends HTTP hosting and 0.135.28 adds compiler-private debug instrumentation to the checked
static/shared/mixed module workflow. Public language remains 0.24. Private source
execution uses ABI2502; published ABIs 3/4/5 and earlier module formats keep their
meaning. This does not publish language 0.25 or its normal build/debug workflow.

Architecture `nex.private-task-architecture/6` extends /4 with
`"instrumentation":"debug"` and an explicit `debug_timeout_ms` in 1..3600000.
Components retain the six fields of /3-/5, including consumer instantiations.
Architecture /5 remains profile-only; combined profile/debug is not implemented.
The schema is [private-task-architecture-v6](../llm/private-task-architecture-v6.schema.json).

Each `nex.private-task-module/6` record has a checked
`nex.private-task-module-debug/1` extension. It includes the immutable registry
accessor and original function/source-unit hashes, points, initialized lexical
bindings, source component, actual machine component and physical image. A
consumer-emitted generic retains its template source and the consumer's concrete
trait method targets. Component labels map to explicit bounded internal registry
keys generated by the compiler; consumers must use this map rather than choosing
a different hashing algorithm.

The host resolves every selected component registry in the fixed loaded image
closure, then calls `nex_task_debug_prepare_registries` before source execution.
Original tables stay in their EXE/DSO owners. One common runtime owns the existing
catalog ABI2, task/frame publications and stop marker. This does not change the
88-byte execution descriptor or create an executor while preparing metadata.
The planner checks runtime count/text/storage limits and per-reader text bounds;
the runtime independently checks the actual registry batch before execution.

`sourceExceptionTaskModuleDebugContext` returns a compiler-derived, unlinked
`nex.private-task-debug/2` context. It contains the complete explicit source
context and architecture, checked plan/catalog identity, source/consumer/image
mapping, dense code ranges and lexical metadata. The artifact caller binds the
actual executable and code/runtime image paths, SHA256 and UUID/build-ID after
linking. Source identities are distinct from image pins. There is no graph
revision or invented archived identity. The complete linked manifest must fit
the debugger's 8 MiB manifest bound.

Load the matching private context explicitly:

```text
command script import /path/to/debug/lldb_nex.py
nex-load-private-task-debug /path/to/debug.json --compiler /trusted/nex
nex-task-break function leaf::fail
run --nex-task-workers 2
nex-task stack
nex-task values
nex-eval leaf_value+1
nex-task out
nex-task next
nex-task continue
```

Use source line breakpoints through the same logical debugger or NEX-DAP.
Inspection requires a real process all-stop and borrows stable retained values;
it does not invoke inferior functions or retain source owners. A logical task can
move among workers without losing its source call chain. Catch names become
visible only after initialization. Unwinding retires callee frames, while
step-out/next finds the actual retained caller and handler. Deadlines keep
advancing while the process is stopped; no deadline suspension is implied.

The reader checks the entire loaded image closure, original registry ranges,
dense/original code associations, module-qualified step symbols and immutable
metadata before reading values. Stack results include a separate unarchived
source-origin record with source component, machine component and image.
Selected unused code remains part of the catalog even without an active frame.
Static components absorbed into another image do not acquire a fabricated DSO.

Checked watch evaluation runs in the explicitly selected external compiler.
It reloads the embedded source context, derives the module plan and debug context
again, and compares every source/consumer/function/catalog identity before
checking the expression. A `nex.private-task-debug-frame/2` capture retains the
same build/source/catalog and stop identities. Captures remain inspectable with
matching compiler/manifest after the process exits and source files disappear.
File/scope/task/channel authority remains opaque; a File diagnostic identity and
pure equality do not grant IO. Effectful and unavailable resource watches retain
their existing rejected semantics.

Conformance compiles real O0/O2 static/shared/mixed applications and compares
ordinary execution with the independent AST and TaskIR schedulers. Live LLDB
covers library/caller/catch values, watch/capture with hidden source, File/FFI
ownership cleanup, consumer-owned trait specializations, component labels and
deadlines while stopped. NEX-DAP checks logical stacks, caller watches, exception
unwind, stale frame rejection and next. Separate relocation checks hide original
images while unchanged copied images run and remain inspectable. Exact commands,
image/context/capture hashes and raw debugger exchanges are retained by the test
artifacts. These checks do not claim broad installed-SDK/platform acceptance.

Architecture /6 supports an HTTP root through the same checked closed image
plan and catalog. The matching private HTTP fixture prepares every registry
before serving requests and enables NEX_TASK_DEBUG_COMPLETION_ENABLED together
with NEX_TASK_DEBUG_ENABLED. Shared hosts use libnex-private-runtime-http.
A source frame retains the real Request value: inspect req.request_id, req.path,
req.user and req.body in the caller. X-Request-Id binds that request to its actual
response. A logical task ID is separate from the HTTP request ID. All-stop pauses
all requests and native threads; this is not selective non-stop debugging.

A requested out/next must also stop when its selected task terminates, since an
HTTP server remains alive without another source point. The optional runtime
completion marker publishes only catalog/task/generation identity after source
frames have retired. It runs outside scheduler and debug locks, and the reader
checks the actual pinned runtime address, terminal flag and empty stack. It does
not expose a stale source frame, suspend deadlines or alter response handling.
Completion markers auto-continue without an active matching logical step plan.
Catalog ABI2, execution ABI2502 and published source ABIs stay unchanged.

The HTTP conformance group covers O0/O2 static/shared/mixed servers, caught and
uncaught errors, owned File/FFI cleanup, consumer-owned templates, real TLS,
request identities and a deadline that expires while stopped. A background
request queues during all-stop and completes under resume with its own identity.
NEX-DAP checks real HTTP terminal step-out, pure caller watches, stale frame and
variables rejection, joined shutdown and empty terminal stacks. Raw debugger
protocols and offline checked frame captures are retained. These are private
source-checkout tests, not installed public SDK acceptance. HTTP request profile
correlation and combined debug/profile instrumentation remain pending.

Public build/project/debug
CLI integration, packaged capture/replay/IDE, general DLL loading/unloading,
complete platform/SDK delivery and explicit history-preserving 024→025 migration
also remain pending. The original language/toolchain/Studio/converter/accelerator
and measured quality/performance goals stay open. Sanitizers are authorized;
security audit and fuzz campaigns remain deferred by the user.
