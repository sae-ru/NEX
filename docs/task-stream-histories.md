# Genuine023 histories for explicit private024 migration

The expanded migration suite uses five real histories created by the installed
macOS ARM64 SDK0.133.5, language023. Each history has three distinct semantic
revisions produced by ordinary `nex check`. SQL exports retain all16 tables,
their schema and logical identities. These are compiler-produced archives;
their language metadata is not edited to manufacture an older history.

The fixtures cover imported generic File wrappers, immutable File aliases in
lists/results/enums, pure snapshot callables with Unicode/finite numbers,
working whole-file task writes, and locked local/standard library imports.
The generic module includes a pure File identity helper. Native requirement
classification lifts pure helpers consistently with actual continuation
emission; it does not grant filesystem effects or bypass effect checking.
The producer compiler SHA256 is recorded in every fixture. Per-revision source
bundles, expected outcomes, physical sources and the current dependency lock
are retained. Each uniquely named JSON/SQL pair is checked before restoration.

`task_file_stream_histories` migrates every archived revision into a separate
copy of its complete history through explicit C++ TaskStreams024 APIs. It
checks preserved rows/schema/IDs, the new HEAD, idempotence and unchanged
physical sources/manifests/locks. Independent AST and compiled native results
must agree; native execution runs with physical source files hidden. The pure
client entry is emitted and executed by Node while server file code is pruned.
This client check does not claim browser filesystem authority or task IO in
standalone synchronous TypeScript exports.

Every history also rejects a false declared024 origin, a stale expected HEAD
and implicit source synchronization without changing its store. Ordinary
public CLI synchronization refuses the new future-language HEAD. The retained
parser still produces E_TASK_UNIMPLEMENTED for023 task-stream execution and
preserves the successful whole-file write behavior. The optional
`--retained-sdk PATH` reruns these old revisions with the pinned installed
producer binary, after migration, without changing any graph rows.

This expands source-history conformance; it does not publish024, prove arbitrary
in-flight syscall cancellation or replace matching full/SAN/SDK/platform
acceptance. Genuine mixed FFI/resource histories and the other planned language,
server, accelerator, UI/platform and measurement work remain open.
